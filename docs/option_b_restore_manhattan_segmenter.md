## Why this exists (read first)

I previously drafted a plan to re-introduce the Manhattan tree-search
segmenter inside `whale-grammar`. The user pushed back: if Manhattan
tree-search is the right reconstruction of Sharma 2024, it belongs in
**whale-ici-data**, where the unified corpus is built. That way every
downstream consumer benefits and `whale-grammar` stays a thin renderer.

Concretely, today `whale-ici-data/src/pipeline/E_classify.py` does **two
things differently from whale-gpt**:

1. **Rhythm.** Per-(rhythm, n_clicks) centroids → MSE nearest-centroid of
   matching length. One input row in, one rhythm label out. No
   segmentation. (Sharma 2024 reconstruction; not whale-gpt's algorithm.)
2. **Ornament.** Temporal-neighbour heuristic: a coda is ornamented if the
   nearest same-whale neighbour within ±W s has `n_clicks - 1` clicks.
   `select_best_ornament_config` sweeps mode/window/same_whale on the
   labelled set and picks max-F1. **Cannot fire without timing** → Hersh
   gets 0 ornaments.

Manhattan tree-search (whale-gpt's `0_extract_codas.py`) instead segments
ICI sequences against length-specific cumulative-ICI templates, with
class-100 markers detecting structural extra clicks. It's the more
principled algorithm and works without timestamps. That's what we want
upstream.

While we're rewriting upstream, also **add `tempo`** to the schema —
deterministic from `coda_duration_s`, useful to anyone, no reason to make
every consumer recompute it.

## Centroid building (changes from upstream's current code)

Current upstream uses `MIN_CLUSTER_SIZE = 5` per (rhythm, n_clicks) cell
and does NOT filter ornamented training rows. **Switch to:**

```python
def build_centroids():
    """Returns ({class_id: cumulative_mean_vec}, {class_id: n_icis}).

    Built from the labelled DSWP subset; ornamented training rows are
    EXCLUDED so extra clicks do not smear the rhythm templates.
    """
    labelled = pd.read_csv(LABELED_CSV)
    rhythms = pickle.load(open(LABELED_RHYTHMS, "rb"))
    ornaments = pickle.load(open(LABELED_ORNAMENTS, "rb"))
    assert len(labelled) == len(rhythms) == len(ornaments)

    df = labelled.assign(_class=rhythms, _ornament=ornaments)
    df = df[df["_ornament"] == 0]   # CRITICAL: drop ornamented training rows

    ici_cols = sorted(
        [c for c in df.columns if c.startswith("ICI") and c[3:].isdigit()],
        key=lambda c: int(c[3:]),
    )
    means = {}
    for class_id, group in df.groupby("_class"):
        if class_id < 0:
            continue
        block = group[ici_cols].to_numpy(dtype=float)
        block = np.where(np.isnan(block), 0.0, block)
        nonzero = (block != 0).sum(axis=1)
        min_len = int(nonzero.min())
        if min_len < 2:
            continue                # class 17 has variable-length rows; skip
        head = block[:, :min_len]
        sums = head.sum(axis=1, keepdims=True)
        cum = np.cumsum(head / sums, axis=1)
        means[int(class_id)] = cum.mean(axis=0)
    coda_lengths = {k: len(v) for k, v in means.items()}
    return means, coda_lengths
```

Verified 2026-05-03: yields 17 classes (0..16), template lengths
`[2..9]` ICIs. Class 17 is variably-length noise/catchall in the
upstream labels and gets dropped.

## Segmenter (port from whale-gpt)

Reference: `~/Code/whale-gpt/scripts/0_extract_codas.py`. The previous
local `whale-grammar/src/pipeline/E_classify.py` (now deleted; recover
via `git show 76b4c60:src/pipeline/E_classify.py` if needed) was a
faithful port. Drop it into `whale-ici-data/src/pipeline/E_classify.py`.

Constants (do NOT change without benchmarking):
```python
THRESHOLD = 0.1
SEQUENCE_EVAL_INDEX = 9
CANDIDATE_LIMIT = 100
EXTRA_CLICK_PENALTY = 0.05
ORNAMENT_CLASS = 100
```

Core algorithm (verbatim from the old port):

```python
class TreeNode:
    __slots__ = ("val", "children")
    def __init__(self, val):
        self.val = val
        self.children = []
    def add_child(self, n): self.children.append(n)

    def best_path(self, _root=True, _path=None, _score=0.0):
        path = (_path or []) + [(self.val[0], self.val[2], self.val[3])]
        if self.val[0] == ORNAMENT_CLASS:
            score = _score + EXTRA_CLICK_PENALTY
        else:
            score = _score + (self.val[1] if isinstance(self.val[1], (int, float)) else 0.0)
        if not self.children:
            return [(path, score)] if not _root else (path[1:], score)
        results = []
        for child in self.children:
            results.extend(child.best_path(_root=False, _path=path, _score=score))
        results.sort(key=lambda x: x[1])
        if _root:
            return results[0][0][1:], results[0][1]
        return results


def _coda_distances(seq, means):
    arr = np.asarray(seq, dtype=float)
    total = arr.sum()
    if total <= 0:
        return {}
    norm = np.cumsum(arr / total)
    out = {}
    for cls, mean in means.items():
        m = len(mean)
        if len(arr) < m:
            continue
        slc = norm[:m]
        if int(np.sum(np.abs(slc - 1.0) < 1e-10)) == 1:
            out[cls] = float(np.sum(np.abs(slc - mean)))
    return out


def _candidates(seq, means):
    return sorted(_coda_distances(seq, means).items(), key=lambda kv: kv[1])


def _expand(tree, cands, seq, eval_idx, start, means, lens):
    for cls, score in cands[:CANDIDATE_LIMIT]:
        clen = min(len(seq), lens[cls])
        end = start + clen
        rem = seq[clen:]
        child = TreeNode((cls, score, start, end))
        if len(rem) > 1:
            _grow(child, rem, eval_idx, end, means, lens)
        elif len(rem) == 1:
            child.add_child(TreeNode((ORNAMENT_CLASS, 1.0, end, end + 1)))
        tree.add_child(child)


def _grow(tree, seq, eval_idx, start, means, lens):
    cands = _candidates(seq[:eval_idx], means)
    if cands:
        _expand(tree, cands, seq, eval_idx, start, means, lens)
        return tree                                     # <-- (*) early return
    if not any(c.val[0] == ORNAMENT_CLASS for c in tree.children):
        skip = _candidates(seq[1:eval_idx + 1], means)
        if skip:
            orn = TreeNode((ORNAMENT_CLASS, 1.0, start, start + 1))
            _expand(orn, skip, seq[1:], eval_idx, start + 1, means, lens)
            tree.add_child(orn)
    if eval_idx > 1:
        _grow(tree, seq, eval_idx - 1, start, means, lens)
    return tree


def segment(seq, means, lens):
    if len(seq) < 2:
        return []
    root = TreeNode((None, 0.0, 0, 0))
    _grow(root, list(seq), SEQUENCE_EVAL_INDEX, 0, means, lens)
    if not root.children:
        return []
    path, _ = root.best_path()
    return path
```

### Known property at `(*)` — the early return

When candidates match at the current `eval_idx`, the segmenter expands
those children and **does not** also recurse with a smaller `eval_idx`.
This is faithful to whale-gpt
(`~/Code/whale-gpt/scripts/0_extract_codas.py:156-200` — the
smaller-eval recursion is in the `else:` branch). Consequence: ornaments
are systematically under-detected when a longer template fits. Don't
"fix" without explicit user buy-in — it's a published algorithm choice,
not a bug.

## Materialising output rows (replaces upstream's `classify_rhythms`)

Upstream's current `classify_rhythms` returns a list aligned to input
rows. With segmentation, one input row may produce 1+ output rows.
Restructure:

```python
def _emit(src_row, *, cls, ornament, icis, t_offset, k, n_segs, ici_cols):
    out = src_row.to_dict()
    n_clicks = len(icis) + 1
    out["n_clicks"] = int(n_clicks)
    duration = float(np.sum(icis)) if len(icis) else 0.0
    out["coda_duration_s"] = duration
    if pd.notna(out.get("time_in_recording_s")) and t_offset > 0:
        out["time_in_recording_s"] = float(out["time_in_recording_s"]) + float(t_offset)
    if n_segs > 1 and pd.notna(src_row.get("source_coda_id")):
        out["source_coda_id"] = f"{src_row['source_coda_id']}_seg{k}"
    out["rhythm"] = int(cls) if cls is not None and cls >= 0 else pd.NA
    out["extra_click"] = pd.NA if ornament is None else int(ornament)
    out["tempo"] = tempo_bucket(duration) if duration > 0 else pd.NA
    for col, v in zip(ici_cols, normalize_icis(list(icis), n_clicks)):
        out[col] = v
    return out


def classify(unified: pd.DataFrame) -> pd.DataFrame:
    print("E_classify: building Manhattan-tree-search centroids "
          "(ornament-filtered training rows)...")
    means, lens = build_centroids()
    print(f"  {len(means)} rhythm classes; lengths {sorted(set(lens.values()))} ICIs.")

    ici_cols = [c for c in ICI_COLUMNS if c in unified.columns]
    new_rows = []
    n_unmatched = 0
    n_orn = 0
    n_segs_total = 0

    for _, row in unified.iterrows():
        vals = pd.to_numeric(row[ici_cols], errors="coerce").to_numpy()
        icis = vals[np.isfinite(vals) & (vals > 0)]
        path = segment(icis, means, lens) if len(icis) >= 2 else []

        if not path:
            new_rows.append(_emit(row, cls=None, ornament=None,
                                  icis=icis, t_offset=0.0, k=0, n_segs=1,
                                  ici_cols=ici_cols))
            n_unmatched += 1
            continue
        non_marker = [(j, c, s, e) for j, (c, s, e) in enumerate(path) if c != ORNAMENT_CLASS]
        n_segs = len(non_marker)
        for k, (j, cls, s, e) in enumerate(non_marker):
            ornament = (j + 1 < len(path) and path[j + 1][0] == ORNAMENT_CLASS)
            new_rows.append(_emit(row, cls=cls, ornament=int(ornament),
                                  icis=icis[s:e], t_offset=float(np.sum(icis[:s])),
                                  k=k, n_segs=n_segs, ici_cols=ici_cols))
            n_orn += int(ornament)
            n_segs_total += 1

    out = pd.DataFrame(new_rows)
    out["rhythm"] = out["rhythm"].astype("Int64")
    out["extra_click"] = out["extra_click"].astype("Int64")
    out["tempo"] = out["tempo"].astype("Int64")
    print(f"E_classify: {len(unified):,} input -> {len(out):,} segmented codas "
          f"({n_segs_total:,} matched, {n_unmatched:,} <NA>); "
          f"{n_orn:,} ornaments.")
    return out
```

Drop the old `validate_rhythm`, `select_best_ornament_config`,

## Schema change (upstream `schema.py`)

Add `tempo` to `UNIFIED_COLUMNS`, between `extra_click` and the ICI
block. Keep `rhythm` and `extra_click` semantics, but update the comment
on `extra_click` since it's no longer "NaN where neighbour timing isn't
available" — it's now structural.

```python
TEMPO_THRESHOLDS = (0.45, 0.61, 0.93, 1.08)


def tempo_bucket(duration_s: float) -> int:
    """Sharma 2024 tempo bucket 1..5 from coda duration (seconds)."""
    for i, thr in enumerate(TEMPO_THRESHOLDS):
        if duration_s < thr:
            return i + 1
    return len(TEMPO_THRESHOLDS) + 1
```

```python
UNIFIED_COLUMNS = [
    ...
    "rhythm",       # 0..17 rhythm cluster id (Sharma 2024 numbering); NaN if not classifiable
    "extra_click",  # 0/1 ornament flag from the Manhattan segmenter; NaN if the segment itself is unmatched
    "tempo",        # 1..5 Sharma 2024 tempo bucket from coda_duration_s; NaN if duration is missing/zero
] + ICI_COLUMNS
```

`tempo_bucket` lives in `schema.py` so any consumer can import it.

## Things explicitly NOT to do

- **Don't keep both classifiers running** (upstream MSE-nearest-centroid
  AND Manhattan tree-search). Pick one, replace cleanly.

- **Don't fix the greedy `(*)` early-return** without explicit user
  buy-in and benchmarks. It's the published whale-gpt algorithm.

- **Don't re-introduce `MIN_CLUSTER_SIZE`** from upstream's current
  code. The Manhattan segmenter uses one mean per class (not per
  (class, length)), and class 17 is dropped via the `min_len < 2` check.

- **Don't move centroid building back to `dswp_dominica_codas.csv`** —
  the old whale-gpt path. whale-ici-data already ships
  `sw_combinatoriality_*` files, which are aligned per-row labels. Use
  those.

- **Don't compute tempo locally in whale-grammar after upstream lands.**
  That's what the second commit is FOR — removing duplicated work.

- **Don't compute rubato in upstream.** Rubato is a contextual,
  rendering-script concept (per-coda symbol relative to the previous
  same-whale coda). Keep it where the rendering happens — in
  whale-grammar's `B_classify`.
